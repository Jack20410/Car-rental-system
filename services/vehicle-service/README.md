# Vehicle Service - Car Rental System

## 1. Service Overview
The **Vehicle Service** is a core microservice responsible for managing the complete lifecycle of rental vehicles within the Car Rental ecosystem. It handles vehicle cataloging, search, detailed capability listing, image uploads, and availability status tracking. This service essentially connects `car_provider` users (from the User Service) with the fleet they manage, ensuring customers always see up-to-date car listings and details.

## 2. Tech Stack
- **Runtime Environment:** Node.js
- **Web Framework:** Express.js
- **Database:** MongoDB (via Mongoose ODM)
- **Dependency Injection:** Awilix (Implementing Clean Architecture principles)
- **Authentication/Authorization:** JSON Web Tokens (JWT) & Role-based middleware
- **File Uploads:** Multer (for handling vehicle image galleries)
- **Inter-service Communication:** Axios (Communicates with User Service)
- **Testing environment:** Jest & Supertest (with mongodb-memory-server)

## 3. Key Features / Business Logic
- **Vehicle Catalog Management:** Create, read, update, and delete (CRUD) vehicle listings.
- **Image Gallery Uploads:** Supports `multipart/form-data` uploads allowing car providers to upload up to 10 images per vehicle simultaneously.
- **Status Tracking:** Independent endpoints to quickly toggle a vehicle's status natively (`Available`, `Rented`, `Unavailable`).
- **Role-Based Guards:** Creation and modification of vehicles are strictly isolated and guarded for the `car_provider` role specifically. Ownership checks ensure providers can only edit their own vehicles.
- **Service Integration:** Automatically fetches and merges user details (from User Service) when retrieving vehicle information to display the provider's contact information.
- **Activity Logging:** Records critical operations (like adding or updating a car) through an injectable Activity Logger.

## 4. Prerequisites & Environment Variables

### Prerequisites
- [Node.js](https://nodejs.org/) (v16 or higher recommended)
- [Docker & Docker Compose](https://www.docker.com/) (Optional, for containerized environments)
- A running MongoDB instance

### Environment Variables (.env)
Create a `.env` file in the root of the `vehicle-service` directory. Example:

| Variable | Description | Example Value |
|----------|-------------|---------------|
| `PORT` | The port the service runs on | `3002` |
| `MONGODB_URI` | MongoDB Connection String | `mongodb://localhost:27017/vehicle_service_db` |
| `NODE_ENV` | Environment mode (`development`, `production`) | `development` |
| `JWT_SECRET` | Secret key used for validating JWTs generated by User Service | `your_super_secret_key` |
| `USER_SERVICE_URL`| The accessible URL of the User Service | `http://localhost:3001` |

## 5. Local Setup & Running

### Option A: Running Locally with Node.js
1. **Install dependencies:**
   ```bash
   npm install
   ```
2. **Setup environment:**
   Ensure your `.env` file is appropriately configured.
3. **Start the development server:**
   ```bash
   npm run dev
   ```
   *The service will start on `http://localhost:3002`*

### Option B: Running via Docker
1. **Build and start the container:**
   Assuming you have a standard docker-compose configuration at the project root:
   ```bash
   docker-compose up vehicle-service --build
   ```

## 6. API Documentation

### Public Routes

#### 1. Get All Vehicles
* **Method & URL:** `GET /vehicles`
* **Description:** Retrieves paginated vehicle listings. Automatically attaches the `car_provider` user details to each vehicle by silently querying the User Service.
* **Expected Response:** `200 OK`
  ```json
  {
    "success": true,
    "message": "Vehicles retrieved successfully",
    "data": {
      "vehicles": [...],
      "pagination": { "total": 10, "page": 1, "pages": 1 }
    }
  }
  ```

#### 2. Get Vehicle By ID
* **Method & URL:** `GET /vehicles/:id`
* **Description:** Retrieves complete details of a single vehicle along with its provider's merged information.
* **Expected Response:** `200 OK`

### Protected Routes (Requires Header: `Authorization: Bearer <token>`)
*Note: These routes require the authenticated user to explicitly possess the `car_provider` role.*

#### 3. Create a Vehicle
* **Method & URL:** `POST /vehicles`
* **Description:** Creates a new car listing. Accepts `multipart/form-data` for image arrays.
* **Request Payload (Form-Data representation):**
  - `name`: "Camry"
  - `brand`: "Toyota"
  - `modelYear`: 2023
  - `licensePlate`: "ABC-1234" (Must be unique)
  - `rentalPricePerDay`: 50
  - `seats`: 5
  - `transmission`: "Automatic"
  - `fuelType`: "Gasoline"
  - `carType`: "Sedan"
  - `images`: [File Uploads]
* **Expected Response:** `201 Created`
  ```json
  {
    "message": "Vehicle created successfully",
    "data": {
      "_id": "60d0fe4f5311236168a109ca",
      "brand": "Toyota",
      "images": ["/uploads/vehicles/xyz.jpg"],
      "status": "Available"
    }
  }
  ```

#### 4. Update Vehicle
* **Method & URL:** `PATCH /vehicles/:id`
* **Description:** Updates vehicle details or appends new images. Ownership verified.
* **Expected Response:** `200 OK`

#### 5. Update Vehicle Status
* **Method & URL:** `PATCH /vehicles/:id/status`
* **Description:** Specifically toggles the vehicle availability independent of other details.
* **Request Payload (JSON):**
  ```json
  {
    "status": "Rented"
  }
  ```
* **Expected Response:** `200 OK`

#### 6. Delete Vehicle
* **Method & URL:** `DELETE /vehicles/:id`
* **Description:** Permanently deletes a vehicle if the requester owns it.
* **Expected Response:** `200 OK`

#### 7. Delete Vehicle Image
* **Method & URL:** `DELETE /vehicles/:id/images`
* **Description:** Removes a single image from the database and deletes the physical file.
* **Request Payload (JSON):**
  ```json
  {
     "imagePath": "/uploads/vehicles/xyz.jpg"
  }
  ```
* **Expected Response:** `200 OK`

## 7. API Testing Guide

### Using cURL

**1. Create a vehicle (Requires Form-Data):**
```bash
curl -X POST http://localhost:3002/vehicles \
  -H "Authorization: Bearer YOUR_PROVIDER_JWT_TOKEN" \
  -F "name=Civic" \
  -F "brand=Honda" \
  -F "modelYear=2022" \
  -F "licensePlate=XYZ-9876" \
  -F "rentalPricePerDay=45" \
  -F "seats=5" \
  -F "transmission=Automatic" \
  -F "fuelType=Gasoline" \
  -F "carType=Sedan" \
  -F "images=@/path/to/your/car_image.jpg"
```

**2. Update Vehicle Status:**
```bash
curl -X PATCH http://localhost:3002/vehicles/60d0fe4f5311236168a109ca/status \
  -H "Authorization: Bearer YOUR_PROVIDER_JWT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"status":"Rented"}'
```

**3. Get All Vehicles:**
```bash
curl -X GET http://localhost:3002/vehicles
```

### Using Postman
1. **To Create a Vehicle:** Create a **POST** request to `http://localhost:3002/vehicles`. Under the **Authorization** tab, set it to **Bearer Token** and insert a token representing a `car_provider`. Under the **Body** tab, select **form-data**. Add the required fields as Text (e.g., Key: `brand`, Value: `Honda`) and add the `images` key, changing the type from Text to **File** to select images from your computer. Hit Send.
2. **To Update Status:** Create a **PATCH** request to `http://localhost:3002/vehicles/{id}/status`. Use raw JSON body `{"status": "Unavailable"}`.

## 8. Database Schema

Below is the Entity Relationship table mapping directly to the `Vehicle` Mongoose schema collection.

| Field | Type | Attributes | Description |
|-------|------|------------|-------------|
| `_id` | ObjectId | Primary Key | Auto-generated MongoDB reference ID |
| `car_providerId`| ObjectId | Required, Ref:`User` | ID linking to the user who owns this vehicle |
| `name` | String | Required | General model name |
| `brand` | String | Required | Manufacturer (e.g., Toyota, Ford) |
| `modelYear` | Number | Required | Year of manufacture |
| `licensePlate`| String | Required, Unique | Unique government identifier |
| `rentalPricePerDay`| Number | Required | Daily cost calculation base |
| `images` | [String] | Required Array | Paths defining the image locations |
| `seats` | Number | Required | Total seating capacity |
| `carType` | String | Enum Set | E.g., `Sedan`, `SUV`, `Convertible`, `Hatchback` |
| `transmission`| String | Enum Set | `Manual` or `Automatic` |
| `fuelType` | String | Enum Set | E.g., `Gasoline`, `Electric`, `Hybrid` |
| `status` | String | Enum Set | Defaults to `Available` (`Rented`, `Unavailable`) |
| `createdAt` | Date | Default | The specific timestamp of database creation |
